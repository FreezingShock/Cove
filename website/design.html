Design system

One set of tokens for the app and the site.

Every value on this page comes from design/tokens.json. The Swift app and the website both build from that file, and CI fails the build if a generated value drifts from it.

Five rules

  1. Cream is the base. Ink is the only text color.
  2. Aqua is a fill, never text. Ink sits on it, so the label keeps its contrast.
  3. Radii nest. An inner radius is the outer radius minus the inset.
  4. Spacing sits on a 4 pt scale. 44 is a hit target, not a gap.
  5. Bounce in, never out. Anything that closes uses a spring with no bounce.

Contrast

Text must hold 4.5:1 on the surface it sits on. The build checks these pairs and fails if one falls short. Ratios are computed with translucent colors composited over the surface.

Motion

Springs, matched to the app.

Each spring is Spring(duration:bounce:) in the app and a linear() curve on the web, so both settle the same way. Press a track to see the spring run. With Reduce Motion on, the app swaps each spring for a 0.2 s fade, and the site stops the travel.

Sync

How this page stays in step.

  1. Edit design/tokens.json.
  2. Run python3 scripts/build-tokens.py. It rewrites website/css/tokens.css, website/css/type.css, Inlet/InletTheme.swift and every generated block on this page.
  3. CI runs the same script with --check on every pull request that touches these files. A stale block fails the Website workflow.

SF Pro only ships on Apple systems, so this page shows the app's type spec and the website's Figtree rendering side by side.
